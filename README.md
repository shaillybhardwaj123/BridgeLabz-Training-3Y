## Commit Message Guidelines

Use clear and meaningful commit messages to describe your work.

### Commit Message Format
```text
[YourName] <Action>: <clear, concise commit message>
```

#### Allowed Actions:
- **`Add`**: When creating new files, exercises, or assignments.
- **`Refactor`**: When rewriting/restructuring existing code without changing behavior.
- **`Fix`**: When correcting bugs, alignment, or layout issues.
- **`Update`**: When modifying existing documentation (like reviews or progress tracker).

### Examples
- `[John] Add: HTML Forms Assignment`
- `[John] Add: CSS Flexbox Practice`
- `[John] Add: Bootstrap Grid Exercises`
- `[John] Refactor: Responsive Navbar`
- `[John] Fix: CSS Media Query Issue`
- `[John] Update: Weekly Review`

### ⚠️ Avoid Vague Messages
Never use generic or single-word commit messages such as:
- ❌ `update`
- ❌ `done`
- ❌ `changes`
- ❌ `final`
